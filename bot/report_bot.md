**Выбранная технология**

В качестве вариативного задания была выбрана разработка многофункционального асинхронного Telegram-бота «Виртуальная лаборатория». Данная технология представляет собой сложную систему взаимодействия клиента и сервера, где бот выступает в роли интеллектуального посредника между базой учебных материалов и пользователем.

Выбор данной технологии обусловлен несколькими ключевыми факторами:

1.  _Актуальность:_ Проблема быстрого поиска методических указаний к лабораторным работам в приложении или на сайте «Виртуальная лаборатория» по естественно-научным дисциплинам (физика, химия, биология) актуальна для учащихся 7-9 классов.
2.  _Сложность реализации:_ Для создания бота требуется понимание того, как программы обмениваются данными в сети, умение писать асинхронный код, а также навык структурирования информации.
3.  _Гибкость интерфейса:_ В отличие от классических консольных приложений, разработка бота позволяет изучить проектирование пользовательских интерфейсов в рамках мессенджера, используя событийную модель управления кнопками.

Для реализации проекта был выбран современный и высокопроизводительный стек, обеспечивающий стабильную работу системы:

- _Язык программирования:_ Python 3.10+.
- _Основной фреймворк:_ aiogram 3.x.
- _Среда выполнения:_ AsyncIO.
- _Сетевой протокол:_ HTTPS
- _Инструменты разработки:_ Git (для версионного контроля), PyCharm (в качестве IDE), Markdown (для подготовки технической документации).

**Исследование предметной области**

**Анализ архитектуры взаимодействия**

В ходе исследования протоколов взаимодействия с Telegram Bot API были изучены два основных метода получения обновлений:

1.  _Webhooks:_ Сервер Telegram отправляет HTTPS-запрос на сервер бота при каждом новом событии. Требует наличия выделенного IP-адреса и SSL-сертификата.
2.  _Long Polling:_ Бот сам отправляет запросы к серверу Telegram и удерживает соединение открытым до появления новых данных.

Для реализации проекта был выбран метод Long Polling, так как он более гибок в процессе локальной разработки и отладки, а также не требует сложной настройки сетевой инфраструктуры на начальном этапе.

**Ключевые подсистемы бота**

Для создания полноценной технологии «Виртуального помощника» было выделено и спроектировано три базовых модуля:

1.  _Подсистема диспетчеризации:_ Главный узел, который принимает входящие «апдейты» (сообщения, нажатия кнопок) и перенаправляет их соответствующим обработчикам (хендлерам).
2.  _Подсистема обработки событий:_ Набор функций, отвечающих за бизнес-логику. В нашем случае они анализируют callback_data и определяют, какое меню или какой текст лабораторной работы нужно показать.
3.  _Подсистема формирования интерфейса:_ Модуль, отвечающий за динамическую генерацию кнопок. Он должен учитывать контекст (например, не предлагать химию 7-му классу) и обеспечивать корректную навигацию.

**Логика потока данных:**

Процесс обработки запроса в боте можно представить как взаимодействия между Пользователем, Сервером Telegram и кодом бота.

1.  _Пользователь_ нажимает на кнопку «Физика» в интерфейсе мессенджера.
2.  _Клиент Telegram_ отправляет зашифрованный запрос на _сервера Telegram_.
3.  _Код бота_, используя метод getUpdates, забирает это событие (объект CallbackQuery).
4.  _Диспетчер_ определяет, что данные начинаются с префикса sub_, и вызывает соответствующую функцию.
5.  _Бот_ формирует новый текст и клавиатуру, после чего отправляет метод editMessageText обратно на сервер.
6.  _Пользователь_ мгновенно видит обновленное меню в своем чате.

**Исследование структуры учебных данных**

Предметная область (лабораторные работы 7-9 классов) потребовала классификации большого объема текстовой информации. Было решено использовать древовидную структуру хранения в формате словаря Python, где ключами верхнего уровня являются идентификаторы предметов, а вложенными списками - названия работ. Это позволило реализовать мгновенный доступ к списку работ без необходимости перебора всех существующих записей в базе.

Создаем файл main.py. На этом этапе мы подключаем библиотеку и создаем объекты Bot и Dispatcher. Это «сердце» системы, которое отвечает за связь с серверами Telegram.

**Шаг 3: Проектирование базы данных**

Чтобы бот знал названия лабораторных работ, мы создаем структурированный словарь. Использование вложенных списков позволяет автоматизировать создание кнопок: бот просто пробегает по списку и создает столько кнопок, сколько работ указано в базе.

LABS_DATA = {

**Шаг 4: Создание динамических клавиатур**

Для навигации мы используем InlineKeyboardBuilder. Это инструмент, который позволяет генерировать кнопки.

**Важно:** Каждой кнопке мы присваиваем callback_data. Это строковая метка, которую бот получит при нажатии. Например, class_7 скажет боту, что пользователь выбрал 7 класс.

**Шаг 5: Реализация системы переходов**

Это самый сложный технический этап. Создаем функции-обработчики (хендлеры), которые реагируют на нажатия.

- _Метод edit_text:_ Вместо отправки нового сообщения, бот заменяет текст в текущем. Это создает эффект перемещения по страницам приложения.
- _Логика «Назад»:_ В каждую клавиатуру мы добавляем кнопку, callback_data которой ведет на предыдущий этап (например, из выбора предмета обратно к выбору класса).

@dp.callback_query(F.data.startswith("class_"))  
async def select_subject(callback: types.CallbackQuery):  
grade = callback.data.split("\_")\[1\] # Извлекаем номер класса  
await callback.message.edit_text(f"Выбран {grade} класс. Выберите предмет:",  
reply_markup=get_subjects_menu(grade))

**Шаг 6: Финальный экран и вывод подсказок**

Когда пользователь доходит до конкретной работы, бот извлекает её название из словаря по индексу и выводит итоговое сообщение с «Подсказкой». Здесь также добавляется кнопка «Главное меню», чтобы пользователь мог сбросить навигацию и вернуться в начало.

**Модификация проекта**

Базовый шаблон бота был значительно переработан и дополнен функционалом, который превратил его из простого скрипта в структурированную систему. Ниже описаны ключевые модификации.

1.  **Система адаптивной фильтрации контента**

_Что модифицировано:_ Внедрена логика динамического формирования меню в зависимости от выбранных параметров.

_Обоснование:_ В школьной программе предмет «Химия» начинается с 8 класса. Если оставить кнопку «Химия» в меню 7 класса, это приведет к переходу в пустой раздел или ошибке.

_Реализация:_ В коде функции get_subjects_menu было добавлено условие, которое проверяет переменную grade. Если её значение равно "7", кнопка химии просто не генерируется.

\# ...

1.  **Интеграция системного меню команд**

_Что модифицировано:_ Использование метода set_my_commands для создания нативной кнопки «Меню» в интерфейсе Telegram.

_Обоснование:_ Пользователь должен иметь возможность мгновенно вернуться в начало или перезапустить бота из любого подраздела, не используя кнопки навигации.

_Результат:_ Рядом с полем ввода сообщения появилась кнопка, открывающая список быстрых команд.

1.  **Оптимизация навигации через Callback-строки**

_Что модифицировано:_ Переход от простых команд к сложным строковым индексам в callback_data.

_Обоснование:_ Чтобы избежать создания сотен отдельных функций для каждой лабораторной, была создана единая система парсинга данных. Бот передает информацию в формате lab_класс_предмет_индекс. Это позволило сократить объем кода, сделав его универсальным для всех типов работ.

_Что модифицировано:_ Перевод всех ответов бота на разметку Markdown.

_Обоснование:_ Обычный текст выглядит монотонно. Использование жирного шрифта для выделения терминов, эмодзи для визуальной навигации и моноширинного шрифта для формул делает подсказки удобными для чтения с экрана телефона.
